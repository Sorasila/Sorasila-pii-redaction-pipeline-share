## Current decision policy

- Validate and deduplicate exact original-source spans. Retain all nonconflicting matches unchanged. Connected overlap groups include equal spans with different types, nested boundaries and crossing boundaries.
- Locate each group inside an existing trusted detection window that contains every alternative completely. Group conflicts sharing that window into one selection request. Never send the whole long document merely to resolve a local conflict. If no complete trusted window exists, stop with a safe reason.
- Service-generated IDs refer to exact source intervals and their allowed types. Within each connected overlap group, enumerate complete legal nonoverlapping option sets that preserve mandatory matches. The LLM chooses one option ID per group: `{"decisions":{"group_1":"option_n",...}}`. The closed required-key object and per-group enum cannot represent simultaneous competing options. Group options can select multiple compatible spans, one supported type for an interval, or an explicit empty NOT_PII set when no mandatory match exists. There is no longest/latest/fuzzy preference and no model-generated value, offset or boundary.
- Enabled, trusted rule matches are mandatory. A decision cannot remove or change those exact span/type pairs; this preserves numeric field labels. Overlapping mandatory rules are an invalid policy configuration and cannot be resolved by guessing. Earlier finalized replacements remain mandatory during residual rebuilding.
- Preserve non-PII occurrences by context, not global equality replacement. An explicit empty option is a model decision, not a fallback for a failed call. Reject missing/extra groups, unknown/multiple option IDs and the historical per-occurrence decision array. Resolve only the selected service option, then revalidate exact bounds/types/nonoverlap/mandatory matches locally.
- Bound generation before network: at most 64 groups per batch, 12 distinct intervals per group, 64 legal options per group and 4096 enumeration steps per group. These protect local computation; they do not establish model context capacity or a production SLA. Overflow or absence of a legal option stops safely without truncating alternatives or guessing a replacement.

## Budgets and final gate

Conflict selection consumes an extra recovery role call and an actual proxy request. Default one selection attempt per scoped group batch; optional trusted policy allows at most two. Existing shared recovery/call/time limits never reset. Fatal auth/config/model/TLS errors remain fatal. Exhausted/unavailable/invalid selection cannot become clean output.

Apply this mechanism at window/repair merges, the LLM + rule document merge, and residual additions mapped to original source. Redaction and manifest are rebuilt deterministically from the selected original spans. Fresh rules AND LLM verification still covers the entire actual final redacted result before publication. No manual approval, plaintext manifest export, HTTP contract or encryption change.

Diagnostics expose only fixed reasons, stage, counts, attempt and trusted window numbers. Tests cover boundary/type/crossing conflicts, mandatory numeric rules, contextual NOT_PII, exact mapping, invalid decisions, deadlines, recovery/physical caps, unavailable context, and final verification failure. A new live pass does not retrospectively prove which pair failed in an older discarded response.
